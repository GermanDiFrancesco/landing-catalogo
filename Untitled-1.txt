
Guía del Proyecto y Plan de Arquitectura
---

### 1. Objetivos y Alcance
* **Naturaleza del sitio:** Sitio web estático de catálogo institucional / productos para Tecnografic.
* **Cero Base de Datos:** Los datos residen en un archivo estático estructurado (`data/products.json`).
* **Estrategia de carga de datos:** Carga inicial ultrarrápida del HTML/CSS de la página. Una vez cargado el DOM (o vía `defer`/`requestIdleCallback`), un script JS obtiene de forma asíncrona `products.json` para alimentar el buscador y el catálogo dinámico.
* **Fase inicial:** Configurar únicamente la **estructura principal de navegación** y las vistas macro (Inicio y Marcas) sin desarrollar todavía la página de detalle individual del producto.

### 4. Propuesta de Stack Tecnológico y Organización de Archivos

* **HTML5:** Semántico y modular.
* **Tailwind CSS:** 
  * ¿Prefieres compilar Tailwind mediante CLI local (`npx tailwindcss -i ./src/input.css -o ./dist/output.css --watch`) o mediante un script de build mínimo con `npm` / CDN de Tailwind para desarrollo?
* **JavaScript:** Vanilla JS modular (ES6), sin frameworks pesados, fácil de mantener por cualquier desarrollador:
  * `js/main.js`: Lógica de navbar móvil y carrusel.
  * `js/search.js`: Carga en segundo plano (`fetch('data/products.json')`) e indexación simple en memoria (filtro por nombre/categoría/marca).
  * `js/catalog.js`: Manejo de tabs de categorías y selección de productos en las vistas de marca.

### 3. Gestión de Datos y Buscador (`products.json`)

- **Estrategia de carga diferida (Non-blocking):**
  1. El HTML y CSS de la página cargan de inmediato para máxima velocidad inicial.
  2. Mediante JavaScript nativo (`window.addEventListener('load', ...)` o `requestIdleCallback`), se hace un `fetch('./data/products.json')` en segundo plano.
  3. El array de productos queda cacheado en memoria para alimentar la búsqueda por autocompletado en tiempo real sin congelar la interfaz.
